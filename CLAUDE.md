# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Track Days** — a 3D third-person arcade racer in Godot 4.7 / GDScript, using
`VehicleBody3D` physics and Kenney CC0 art. The Godot project lives at the repo
root. It is *not* the pseudo-3D OutRun Racer on the wider roadmap.

Deep background lives in `docs/architecture.md` (the why behind every structural
decision, plus a long list of traps already hit), `docs/tuning-journal.md` (how
the handling numbers were measured) and `tools/README.md`. Read
`docs/architecture.md` before changing the track builder, the editor, the
elevation system or the web export — most of the non-obvious constraints are
recorded there and nowhere in the code.

```bash

# Test suite. Exits non-zero on failure; CI gates on it.
"$GODOT" --headless --path . --script tests/run_tests.gd

# Import/parse check (also regenerates .godot/ and the class_name registry)
"$GODOT" --headless --editor --quit --path .

# Parse-check one script. NOTE: prints errors while still exiting 0, so grep the
# output for "SCRIPT ERROR" / "Parse Error" rather than trusting $?.

# Open the editor / run the game
"$GODOT" --path .

# Web export
"$GODOT" --headless --path . --export-release "Web" build/web/index.html
cd build/web && python3 -m http.server 8777   # must be served over HTTP
```

### Regenerating scenes

Several `.tscn` files are generated by committed scripts in `tools/` and must be
regenerated rather than hand-edited (see `tools/README.md`). Order matters:
`build_track.gd` and `build_ui.gd` before `build_race.gd`, which instances
`hud.tscn`.

```bash
"$GODOT" --headless --path . --script tools/build_track.gd   # both circuits
"$GODOT" --headless --path . --script tools/build_ui.gd      # hud.tscn
"$GODOT" --headless --path . --script tools/build_title.gd   # title.tscn
"$GODOT" --headless --path . --script tools/build_editor.gd  # track_editor.tscn
"$GODOT" --headless --path . --script tools/build_race.gd    # race.tscn
```

`build_track.gd` prints a **closure gap** per track and exits non-zero if a
layout does not join up — the gap must be `(0, 0)` with net ±4 turns and height
back to 0. Fix by adjusting straight counts in the layout.

### Two command-line traps

- **Use `--editor --quit`, never `--import`.** Both regenerate `.godot/`, but
  `--import` rewrites `project.godot` and silently drops the `[rendering]`
  section — taking `renderer/rendering_method.web="gl_compatibility"` with it,
  which the web build depends on. If you ever run it, check
  `git diff project.godot`.
- A `--script` run that errors never reaches `quit()` and **hangs forever**.
  Redirect to a file and use a timeout when running these unattended, or a
  broken script looks like a hang.

## Testing

`tests/run_tests.gd` is a hand-rolled `SceneTree` runner, not GUT — the suite is
entirely scene- and physics-dependent, so it needs no fixtures or mocks.

It is **staged by physics frame**: `_physics_process` dispatches groups of tests
at frames 1–8 (setup, then assertions, then a scripted lap-ordering sequence at
every 5th frame). Some tests must run a frame *after* their staging because
containers lay out late and new bodies enter the physics space late.

There is no flag to run a single test. To isolate one, temporarily comment out
the others in the frame-3 dispatch list, or write a throwaway `_diag_*.gd`
`SceneTree` script (the established pattern for handling measurements — findings
go in the tuning journal, then the script is deleted).

The suite writes to `user://test_records.cfg` and `user://test_tracks` by
overriding `GameState.records_path` and `TrackStore.dir`, so it never touches
real saves. Preserve that when adding tests that save anything.

## Architecture

No autoloads. `GameState` is a `RefCounted` with static vars, which survive
scene changes without needing project-settings registration.

### Flow

`title.tscn` (main scene) lists `GameState.all_tracks()` → sets
`GameState.selected_index` → `race.tscn` instances the chosen track at runtime
and drops the car on its `SpawnPoint`. One race scene serves every circuit.
Custom tracks additionally get an **Edit** button that sets `GameState.editing_id`
and opens `scenes/editor/track_editor.tscn`.

### The four load-bearing decisions

1. **Feel lives in a `CarTuning` resource**, not on nodes. `car.tscn` holds
   geometry only. Godot serialises only non-default properties, so the *script
   defaults are the grippy baseline*, `grippy.tres` is intentionally empty, and
   each preset stores only its deltas. Camera framing is in there too, on
   purpose.
2. **Collision is generated, never taken from the art.** The drivable surface is
   a ribbon of quads built along the centreline as one `ConcavePolygonShape3D`
   with `backface_collision = true` (without it the car falls through raised
   sections). Kenney tiles are visual only.
3. **One builder serves the tool and the game.** `TrackBuilder`
   (`scripts/track/track_builder.gd`) is the only thing that turns a layout into
   a circuit: `tools/build_track.gd` bakes the shipped tracks with it, `race.gd`
   builds player tracks with it at runtime. `measure()` is `build(...,
   with_geometry = false)` — the editor recompiles on every mouse move and cannot
   afford to instance GLBs.
4. **Generated scenes are committed**, so the game never depends on `tools/` at
   runtime. Never hand-edit them: instance overrides in a scene silently beat
   values in the sub-scene it instances, which has already left a corrected
   `center_of_mass` inactive in the shipped game.

### Track pipeline

```
painted cells  →  TrackShape.walk (the single definition of a valid loop)
               →  TrackLayout.compile → Compiled{segments, corners, elevation}
               →  TrackBuilder.build → tiles + collision ribbon + 16 gates
```

- `TrackShape` (static, `RefCounted`) treats the cells as a rectilinear polygon
  and is where every editor edit goes; `_accept` prunes and then refuses any edit
  that no longer walks as one simple ring. `TrackLayout.compile` calls `walk`
  too, so editor and compiler can never disagree about validity.
- Corner **radius** is a free per-corner choice because all three Kenney corners
  join the same two centre lines; a size-N corner occupies an NxN block, spending
  N-1 cells of straight either side.
- **Elevation** is an absolute level per segment. Height can only change inside a
  straight (corner tiles are flat end to end), so each run reconciles three
  levels — previous corner, its own, next corner — with `roadRampLongCurved`
  pieces (the eased ramp; the plain `roadRampLong` wedge breaks into its grade at
  a single edge and nothing emits it any more). Requests that do not fit are
  *reduced, not refused*. The start run is flat and the corner before it is
  pinned to ground, which is what makes height close.
- **Banking** is a per-corner choice, `["C", piece, turn, degrees]`, and corners
  are **flat by default** everywhere — a missing 4th element and `0.0` mean the
  same thing, and nothing infers an angle from a corner's radius. The editor
  cycles a corner flat → 1.5° → 2.5° → 4° and back. The centreline carries a roll
  angle per point; both the collision ribbon and the tile meshes are built from
  that one profile, so they cannot disagree. A banked corner is modelled as an **embankment** (inside edge
  at ground level, outside graded back down by the tile edge) because the world
  is one flat plane and a bodily tilted tile clips straight through it.

### Owner rule when packing scenes

Set `owner` on nodes you created and on instanced sub-scene **roots**, never on
an instance's internal nodes — those then serialise on top of the instance and
everything appears twice (this once shipped a car with eight wheels). Only a node
count reveals it; `tests/run_tests.gd` counts.

### Lap timing

16 `Area3D` gates, index 0 on the start line, ordering enforced in
`lap_tracker.gd` so cuts are ignored. Nothing physically stops cutting — grass
grips like tarmac and guardrails are off — so the ordered gates are the only
thing making a time mean anything. Gates hang off `START_LINE_ALONG` (the
gantry's midpoint), *not* arc zero, and each is pushed forward by half its depth
because `body_entered` fires on the box's leading face. Timing accumulates in
`_physics_process` so headless runs reproduce real times.

### Custom tracks are JSON

`TrackStore` writes `user://tracks/*.json`, deliberately not `.tres` — resource
files can name a script to attach, which is wrong for files players swap. Custom
ids are namespaced `user_` so nobody can inherit a shipped track's lap record.

## Web build constraints

Both are asserted in CI and by the test suite:

- **Single-threaded** (`variant/thread_support=false`) — threaded builds need
  `SharedArrayBuffer`, which needs COOP/COEP headers GitHub Pages cannot send.
- **Compatibility renderer for web only** (`renderer/rendering_method.web`), since
  web is WebGL 2 only. Desktop stays Forward+.

Godot rewrites `project.godot` on its own schedule and has dropped the
`[rendering]` override twice, with no warning and a successful-looking export.
Never put load-bearing reasoning in `;` comments there — Godot deletes them.

`export_presets.cfg` is deliberately committed (CI needs it; the web preset holds
no credentials). Godot's exporter can print a configuration error and still exit
0, so the workflow checks the artifacts exist instead.
